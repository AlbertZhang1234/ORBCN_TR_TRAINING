# SAP OData 集成

使用此 Skill 将一个尚未接入 SAP 的应用，快速建设为经过验证且易于维护的 OData 集成。应适配目标仓库已有的语言、框架、依赖注入、配置、日志和测试约定。不要预设 Next.js、TypeScript、某个特定 SAP 服务或某种认证方式。

## 参考资料选择

- 新建连接或接入一个 SAP 服务时，阅读 [连接流程](references/connection-workflow.md)。
- 处理请求、响应和 OData 协议细节时，阅读 [协议细节](references/protocol-details.md)。
- 设计代码结构和通用客户端时，阅读 [实现模式](references/implementation-patterns.md)。
- 排查连接故障或处理生产安全、日志和监控时，阅读 [排障与安全](references/troubleshooting-security.md)。

只读取当前任务需要的参考资料。执行实现任务时，通常必须同时阅读“连接流程”和“实现模式”。

## 核心流程

1. 设计前先检查仓库说明，以及现有的 HTTP、配置与密钥、错误模型、日志、依赖注入和测试模式。
2. 明确 SAP 契约：基础 URL、服务根路径、OData 版本、实体集或操作、认证方式、SAP Client 或租户、网络/代理/TLS 要求，以及是否需要写入。不要猜测凭证或服务路径。
3. 先验证最小的只读连接：请求服务根路径或 `$metadata`，核对状态码和内容类型，再从元数据确认准确的实体、属性、主键、类型、可空性、导航、Action/Function 和并发控制定义。
4. 优先复用项目已有的 HTTP 技术栈。只有当认证、CSRF、Cookie、响应封装、错误和分页等机制确实重复时，才增加共享 OData 协议适配层。
5. 分离三类契约：
   - 传输与协议：HTTP、认证、CSRF、Cookie、OData 响应封装、错误；
   - SAP 服务：服务根路径、实体集、SAP 字段名称和类型、操作；
   - 应用与领域：验证、业务命名、数据映射、业务编排。
6. 先实现读取，再实现写入。只有明确只读连接、服务元数据、权限、CSRF 行为、Payload 结构、主键语义和幂等要求后，才能增加写入功能。
7. 使用确定性的模拟测试和范围严格的在线冒烟测试进行验证。除非用户明确授权且已知安全的测试实体或流程，否则不能为了测试连接而执行真实写入。

## 必须遵守的安全规则

- SAP 凭证和调用应留在服务端，除非架构明确使用可信的平台 Destination 或代理。禁止通过公开配置或浏览器代码暴露密钥。
- 获取 CSRF Token 后，写入时必须沿用获取 Token 时的 Cookie 会话，并同时发送 Token 和 Cookie。Token 与会话状态必须按 SAP 目标、身份、租户或 Client、服务进行隔离。
- 将服务端返回的分页链接视为敏感数据。只能接受预期 SAP 来源和服务根路径下的链接，禁止向调用方任意传入的 URL 转发认证头或 Cookie。
- 按 OData 类型转义字面量。URL 编码不能保证 `$filter` 或主键表达式安全，禁止拼接未经处理的用户表达式。
- 禁止盲目重试写操作。只对瞬时读取失败使用有次数和时长上限的重试策略。只有具备可靠的幂等或结果核对方案时才能重放写操作。
- 服务提供并发控制时，正确使用 ETag 和 `If-Match`/`If-None-Match`。未理解覆盖语义前，禁止默认使用 `If-Match: *`。
- 禁止通过关闭 TLS 校验解决证书问题。应为应用运行时安装或信任必要的企业或 SAP CA 证书链。
- 日志必须隐藏认证信息、Cookie、CSRF Token、客户端证书以及个人或财务数据。保留关联 ID、状态码、耗时、SAP 错误码和有长度限制的安全摘要。
- 使用 SAP 返回的分页链接，不能自行重建分页状态，也不能在无上限的情况下自动拉取全部页面。

## 完成标准

- 目标环境中的只读元数据或实体冒烟测试成功。
- 服务版本、认证方式、SAP Client 或租户、代理/TLS、超时和 CSRF 策略均为显式配置。
- 原始 SAP DTO 与应用或领域模型经过明确映射，并覆盖日期、小数、布尔值、空值、主键和导航属性。
- 错误保留 HTTP 状态、SAP 错误码/消息/详情、关联 ID 和重试分类，同时不泄露密钥。
- 测试覆盖 URL 和查询编码、认证、响应封装、分页和错误；涉及写入时，还须覆盖 CSRF、Cookie 和并发请求头。
- 运维说明列出必要配置以及不会修改 SAP 数据的连接验证命令或测试。

选择适合目标项目的最小实现。若仓库已有合适的 HTTP 抽象或 SAP SDK，不要强行移植某个框架专用的客户端。
